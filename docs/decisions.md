# 決めたことと理由

## 2026-11-12 開発の立ち上げ

- **名前は「目押し成金」**。リポジトリ名は `meoshi-narikin`。
- **構成はアストラクロニクル（Zodiac-Puzzle-Battle）と同じ**：TypeScript ＋ Vite ＋ Vitest、GitHub Actions で GitHub Pages に公開、作業ブランチ → PR → main。
- **試作品の画面はそのまま移した**（`src/ui/app.ts`、型チェックなし）。エンジン（停止制御・抽選・生活の計算）と数値だけ先に `src/game/`・`src/data/` に分け、停止制御の約束をテストにした。画面は作り直すときに分割して型を付ける。
- **保存は端末内（localStorage）**。試作品と同じキー（`meoshi-narikin-v1`）なので、同じブラウザなら試作品の続きから遊べる。

## 試作の段階で決めたこと（仕様書 11章の経緯の詳細）

- **終わりのない成長**：日数で終わるローグライクにはせず、少しずつ（大幅にではなく）良くなる要素を積み重ねる。
- **バトル要素はなし**：モンスターと戦う形（封印リール）はやめ、スロッターの生活に絞った。
- **7とBARは大きく、5ライン、BAR狙い**：日本のスロットの見た目と打ち方に寄せるため。
- **ボーナスは 7・7・7（BIG）と 7・7・BAR（REG）**：左と中は共通、右で見分ける実機の感覚に合わせた。
- **左にスイカが見えたらスイカ以上**：BAR狙いで左にスイカが滑ってきたらレア役、という実機の常識に合わせた。
- **表示と払い出しを必ず一致させる**：当たっていないのに役がそろって見える状態は整合性が取れないため、先読みの停止制御と配列の組み直しでなくした。変則押しのときだけ、実機同様に取りこぼすことがある。
- **バイトは作業ミニゲーム**：ボタン1つで稼げるとスロットを打たなくなるため、検品作業の出来高制にし、スロットより割に合わない程度にした。
- **ホールは各機種3台の9台**：1機種1台では台選びが成り立たないため。普段は他の客が座っていて、イベント日は整理券の番号で選べる台が決まる。
- **ハマりの持ち越しは店ごとのリセット率で決まり、店員さんとの仲で情報が見える**：ハイエナと朝一の立ち回りに読みの要素を入れるため。

## 2026-11-12 図柄を画像にする

- **図柄は画像生成で作った透過PNGを、WebP（480×288）にして `public/symbols/` に置く**。読み込めるまでは今までの手描きの図柄を出す。作ったときのプロンプトは `docs/art-prompts.md`。
- **BARは黒地に金の、傾けない横長の板にした**。最初の赤い傾いた板は、赤7と色も傾きも同じで見分けにくかったため。
- **ボーナス図柄（赤7・BAR・青7）はリール上で光らせる**。実機でもボーナス図柄は明るく見えて狙いやすいため。「最後のリールだけ速く感じる」という意見も受けて、7を見つけやすくする狙いもある。光は画像に描かず画面側で付ける（透過画像に光を描くと縁が汚れやすく、強さも後から変えにくい）。強さと色は `src/data/reels.ts` の `SYMBOL_GLOW`。

## 2026-11-12 更新ボタン

- **アストラクロニクルと同じ、版の確認と更新ボタンを入れた**（仕様書 9.1）。ホーム画面に置いたアプリは閉じても古い版のまま開くことがあるため。
- **知らせと更新ボタンはホーム画面にだけ出す**：打っている最中や改造基盤のルーレット・バイトの途中で読み直すと、結果をやり直せてしまうため（画面の上に常に出す帯にしなかった理由）。押すと保存してから読み直す。

## 2026-11-12 アプリのアイコン

- **金の7とメダルの山、夜の街並み（タワマン）の絵にした**。スロットのゲームだと一目で分かり、「ボロアパートから成り上がる」話も伝わるため。元の絵は `docs/app-icon/app-icon-1024.png`（プロンプトは `docs/art-prompts.md`）。
- **ホーム画面に置くとアプリとして開ける**（`public/manifest.webmanifest`、アストラクロニクルと同じ作り）。ブラウザのタブ用（32・64px）、iPhone のホーム画面用（180px）、Android 用（192・512px）を置いた。

## 2026-11-12 ボーナス図柄以外を小さく

- **ベル・リプレイ・スイカ・チェリーを枠の72%で描き、7とBARの光を強めた**（`SYMBOL_SCALE`・`SYMBOL_GLOW`）。「中と右のリールで7やBARが見えない」という意見を受けて、回っている間にボーナス図柄だけが目に入るようにするため。

## 2026-11-12 右リールの7とBARを1か所に／光を枠ごとに

- **右リールの赤7とBARを1つずつにし、「赤7・リプレイ・BAR」の1か所にまとめた**（11番の赤7をリプレイ、13番のBARをベルに）。中と右で7が見えないという意見を受けたもの。同じかたまりが1周に2回来ると、目で追う目印にならないため。中はいったんそのまま。
  - 右の7を引き込める範囲は狭くなる（ちゃんと目押しが要る）。順押しの約束はテストで確かめ、変則押しのこぼしは1.3%→1.0%に減った。
- **ボーナス図柄の光は、枠ごと裏から金色に照らす形にした**：縁がほんのり光るだけでは、回っている間に分かりにくかったため。

## 2026-11-13 中リールの7も1つに

- **中リールの赤7を1つにした**（10番の赤7をベルに）。ユーザーの依頼。右と同じく、1周に1回だけ通る7を目印に狙う形にそろえる。
  - 0番と10番のどちらを、ベル・リプレイのどちらに替えるか4通りを比べ、停止制御の約束のテストをすべて通るのは「10番→ベル」だけだった（変則押しのこぼし約0.7%）。
  - 左は「7・リプレイ・7」のビタ押しポイントがあるので2つのまま。
  - 八門の扉チャンスで、中の赤7が止まる割合は約67%→約33%（適当に押した場合）に下がる。あわせて、左を先に止めると中に赤7が見えても当たりにならない不具合を直した（中は止まっているリールとのつながりを見ない。仕様書 5.3 の「中リールに赤7が止まれば扉が1つ消える」どおり）。

## 2026-11-13 回り始めの加速

- **3本そろって0.15秒かけて全速まで加速し、ストップボタンは全速になってから受け付ける**（`SPIN_UP_MS`）。「回り始めがバラバラに見える」という意見を受けたもの。調べると3本は同じ時刻・同じ速さで回り始めていたが、止まった状態から次のコマでいきなり全速になるため、目がとらえる順でずれて見えていた。左→中→右と時間差を付ける案もあったが、ユーザーの選択でそろって加速する形にした。全速になってからの速さと目押しの判定は変わらない。

## 2026-11-13 開発者画面

- **パスワード 77777 で開く開発者画面を入れた**（仕様書 9.3）。ユーザーの依頼。お金を最大・全部解放・ゲージ満タンができる。
- **入口は「今の版」を5回続けて押す**：普通に遊ぶ人の目に触れないように。パスワードはコードから読めるので、隠し機能という程度の扱い。
- **「全部解放」で家は買わない**：住まいは見た目と部屋の広さが変わる選択なので、お金を最大にしてから自分で選べるようにした。会員制サロンは「分譲マンション以上」の条件を満たさなくても入れるようにした（`devAll`）。実績のごほうびのお金も出さない。

## 2026-11-14 タブバーと買い物画面、スライドして購入

- **ホームのボタンが多くて窮屈、という意見から、画面の下に4つのタブ（ホーム・パチ屋・買い物・自分）を置いた**（仕様書 9.4）。ほかのボタンの並べ方（ホームに大きいボタン数個）と比べ、ユーザーがタブバーを選んだ。
- **買い物・自分の中は、上のタブと横スワイプでページを切り替える**。ごはん・息抜き・家具・不動産・裏市場を1つの「買い物」にまとめた。
- **家の購入・引っ越しと ¥100,000以上の買い物は、スライドして決める**。ほかの操作（下から出るシート・長押し・カードのスワイプ）も候補に挙げたが、ユーザーが選んだのはこれだけ。
- **タブは打っている最中・バイト・ルーレットの途中は隠す**：途中で別の画面に移ると、結果をやり直せてしまうため。
- **部屋はアニメ調の絵にし、家具は種類ごとに置き場所を決める**（ユーザーの選択）。絵の生成は画像生成AIで行うので、プロンプトを `docs/art-prompts.md` に用意し、絵が届いてから置き方の仕組みと一緒に入れ替える。

## 2026-11-14 金の装飾の見た目

- **ユーザーが見せた参考画像（金の縁取り・光沢のある赤いボタン・紺と紫の背景のゲームアプリ風）に合わせて、見た目を作り直した**（仕様書 9.5）。下のタブや画面の中身は変えていない。
- **台ごとのキャラクターの絵（招き猫・侍・龍など）や部屋の絵は、画像ができてから入れる**。今回は CSS と小さなアイコン（SVG）だけで作れる範囲。
- 上書きは `src/style.css` の最後にまとめた。元の見た目に戻すときは、その部分を消せばよい。

## 2026-11-14 ページ送りを自前に／100G オート／収支は「自分」へ

- **買い物・自分のページ送りを、ブラウザの横スクロールから自前の指の動きの判定に変えた**。iPhone で途中のページに止まったり、スライドして購入のつまみを動かすとページまで動いたりしたため。
- **オートに 100G を足した**（`AUTO_GAMES`）。回している間はボタンが「止める」になり、押すと止まる。
- **最近の収支をホームから外し、「自分」→「収支」に移した**（ユーザーの依頼）。通算の収支や勝ち負けの回数も出し、記録は直近60回まで残す（`HIST_MAX`）。

## 2026-11-14 スライドして購入をやめ、確認の画面にした

- **スライドして購入をやめ、すべての買い物で「購入しますか？」の確認画面を挟み、買った後は「購入しました」の画面を出す**（ユーザーの依頼）。ごはんや不動産を買えたのかどうかが分かりにくかったため。買った後の画面には、支払い・残りの所持金・変わったゲージを出す。
